## Решения

**Структура.** Слой данных отделён от интерфейса:
`fetchMatches` (сеть) → `parseMatches` (разбор ответа) → `Match` (доменная модель) → `utils` (форматирование, фильтр, сортировка) → `useMatches` (состояние) → компоненты.
Компоненты ничего не решают про данные, только отображают. Логика — в чистых функциях, их можно тестировать без рендера.

**Статусы в фильтре.**

- «Предстоящие» — `scheduled`, `live`, `postponed`: всё, у чего ещё нет итогового результата. Идущий матч не завершён, перенесённый ещё будет сыгран.
- «Завершённые» — только `finished`.
- Неизвестный статус (например, если сервер пришлёт `cancelled`) превращается в `unknown`, показывается как «Статус неизвестен» и виден только во «Все». Экран при этом не падает.

**Неочевидные случаи в данных:**

- Счёт 0:0 (m2) — проверяю `score !== null`, а не truthy, иначе нули пропали бы.
- Матч без даты (m7, `startsAt: null`) — показываю «Дата уточняется» вместо 1 января 1970; в сортировке он в конце.
- Поле `minute` есть только у live-матча (m4) — показываю «Идёт · 67′»; в модели отсутствующее поле приводится к `null`.
- Время приходит в UTC — форматирую через `Intl.DateTimeFormat` без `timeZone`, так берётся пояс устройства.
- Длинные названия («Пари Нижний Новгород») переносятся и не ломают карточку.

**Сеть и ответ сервера:**

- `fetch` не бросает ошибку на 404/500 — проверяю `response.ok`.
- Статус 200 не гарантирует JSON — ошибку разбора перехватываю и показываю понятное сообщение. `Content-Type` не проверяю: raw.githubusercontent отдаёт JSON как `text/plain`.
- Ответ разбирается вручную, а не через `as Match[]`: если сломан один матч — он пропускается, если сломан весь ответ — показывается ошибка.
- `cache: "no-store"`, чтобы «Обновить» не получал ответ из кеша браузера. Кеш CDN GitHub (до 5 минут) клиент отключить не может.

**Состояние загрузки:**

- `matches: null` — ещё не загружено, `[]` — загружено, но пусто. Так отличаю загрузку от пустого тура.
- Если обновление упало, старый список остаётся на экране, сверху — сообщение об ошибке. «Обновлено N сек назад» в этом случае не сбрасывается: данные не обновились.
- Защита от гонки запросов: применяется только ответ последнего запроса (`lastRequestId`), чтобы медленный старый ответ не перезаписал свежий.
- Кнопка «Обновить» обязательна: pull-to-refresh в браузере не работает.

**Прочее:**

- В `config.ts` адрес `MATCHES_URL` — заглушка `OWNER/REPO`, по ней сервер отвечает 404. Комментарий в файле говорит, что адрес менять не нужно, поэтому заглушку оставил. Для разработки использовал адрес своего форка — он оставлен в `config.ts` закомментированным. Чтобы увидеть данные, раскомментируйте его вместо заглушки.

## Баги из части 2

1. **Звёздочки.** Две ошибки. `Boolean(favorites.indexOf(id))`: `indexOf` возвращает `-1`, если элемента нет, а `Boolean(-1)` — это `true`, поэтому горели все звёзды; первый добавленный матч имеет индекс `0`, `Boolean(0)` — `false`, поэтому он гас. Вторая: `push`/`splice` меняли тот же массив, и `setFavorites` получал ту же ссылку — React сравнивает по ссылке, решал, что ничего не изменилось, и не перерисовывал экран; изменения всплывали при следующей перерисовке по другой причине.
   → `includes()` вместо `indexOf`, новый массив через функциональное обновление `setFavorites(prev => ...)`. В `FlatList` добавил `extraData={favorites}`, чтобы строки перерисовывались при смене избранного.

2. **«Обновлено N сек назад».** Колбэк `setInterval` создавался один раз (зависимости `[]`) и навсегда запоминал `seconds` из первого рендера, то есть `0`: каждую секунду вызывалось `setSeconds(0 + 1)`, и число застывало на 1. Проп `since` не использовался, поэтому после обновления счётчик не сбрасывался. Интервал не очищался.
   → Храню текущее время (`now`), интервал раз в секунду обновляет его, а секунды вычисляю при рендере как `now - since`. Новый `since` сразу даёт 0. Добавил `clearInterval` в очистку эффекта.
